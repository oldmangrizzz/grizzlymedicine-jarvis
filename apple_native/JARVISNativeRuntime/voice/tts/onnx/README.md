# JARVIS ONNX TTS Branch

**Agent:** ONNX Runtime (C++) branch  
**Architecture:** pocket-tts 2.1.0 (Kyutai FlowLM + Mimi) — NOT vanilla XTTS-v2  
**Runtime deps:** ONNX Runtime C++ API, SentencePiece, nlohmann/json, Accelerate.framework (macOS)  
**Zero Python at runtime.** Build-time export script requires Python + pocket-tts.

---

## Architecture Clarification

The project briefing uses "XTTS-v2" and mentions `text_encoder / gpt_decoder / hifigan`. The actual
oracle was generated by **pocket-tts 2.1.0**, which uses Kyutai's architecture:

| Briefing alias   | Actual module          | Description                                         |
|-----------------|------------------------|-----------------------------------------------------|
| `text_encoder`   | LUTConditioner         | SentencePiece tokenization → embedding lookup        |
| `gpt_decoder`    | FlowLMModel (single step) | Streaming transformer + MLP flow-net (LSD decode) |
| `hifigan`        | MimiModel decoder step | Neural audio codec (SoundStream/Mimi)               |

Voice conditioning is implemented via **KV-cache prefilling**: the voice state safetensors
(`jarvis_voice_state.safetensors`, 46 MB) contains pre-computed KV-cache tensors from the
voice reference audio. These are injected at position 0 of the autoregressive generation.

## ONNX Export Notes

### Pitfall 1: Autoregressive loop
The FlowLM autoregressive loop is **not** exported as a loop. The ONNX model
(`gpt_decoder.onnx`) represents a **single decode step** with explicit KV-cache I/O.
The C++ caller loops and manages cache state between steps. This is the standard
pattern for autoregressive ONNX models (Whisper, GPT, etc.).

### Pitfall 2: KV-cache in-place writes
`complete_kv()` does in-place indexed writes. The export wrapper uses `.clone()`
to produce copy semantics that trace cleanly through `torch.onnx.export`.

### Pitfall 3: Stochastic noise
The `lsd_decode` step samples Gaussian noise. The export uses a fixed seed for
tracing (so it traces deterministically). At C++ runtime, fresh noise is generated
per step using a seeded `std::mt19937`. This is consistent with pocket-tts behavior.

### Pitfall 4: RoPE (Rotary Positional Encoding)
The streaming transformer uses dynamic position offsets stored in the KV-cache state.
These are passed as explicit int64 input tensors (`kv_offset_N`) to the ONNX model.

### Opset
All models use **opset 20** (maximum supported by ONNX Runtime 1.18+).

## Execution Provider Selection (Apple Silicon)

```
Priority 1: CoreML EP  (OrtSessionOptionsAppendExecutionProvider_CoreML)
            → ANE/GPU acceleration via ONNX Runtime's CoreML EP shim
            → Distinct architecture from native MLModel (CoreML sibling branch)

Priority 2: CPU EP with NEON (automatic fallback)
```

The active EP is logged at pipeline construction and available via
`XTTSOnnxPipeline::active_execution_provider()`.

## Known ONNX Export Challenges & Expected Failure Modes

### High-risk: KV-cache tracing fidelity
The stateful transformer's `complete_kv` uses in-place tensor writes. If torch tracing
captures the in-place branch incorrectly, the ONNX model will produce wrong KV updates.
**Mitigation:** export wrapper uses `.clone()` and explicit offset math.

### High-risk: Noise determinism
The ONNX export fixes noise at a single value for tracing. C++ runtime generates noise
from `std::mt19937`. If the noise distribution differs (e.g., different std::normal_distribution
implementation), mel-L2 may be nonzero but still < 1.0 dB (quantitative test passes;
perceptual quality preserved).

### Medium-risk: Mel-L2 ≤ 1.0 dB
If the FlowLM ONNX export has op compatibility issues (e.g., opset 20 ops not supported
in ORT 1.18), generation quality degrades. In this case `test_equivalence` fails and
reports per-prompt L2 values. The tokenizer byte-equiv test is independent and should pass.

### Low-risk: HiFiGAN (Mimi) decoder
Mimi uses standard convolutional layers + a projected transformer. These export cleanly.

---

## Honest Failure Reporting

If `test_equivalence` fails:
- The test prints a table of all 50 prompts with L2 values
- Top-5 worst prompts are reported
- Suspected regression location: FlowLM step export (noise + KV-cache)
- Recommendation: libtorch sibling may fare better (direct PyTorch C++ API, no ONNX tracing)

The acceptance bar is **not lowered** under any circumstances. Mel-L2 > 1.0 dB = fail.

## Operator-gated voice baseline rotation

The active tripwire baseline in `sbom/voice-weights-baseline.json` is not regenerated automatically. If `gpt_decoder.onnx` differs from the baseline, run:

```bash
tools/rotate_voice_baseline.sh --operator-attest \
  --audio-sample <operator-listened-sample.wav> \
  --weights JARVISNativeRuntime/voice/tts/onnx/onnx_models/gpt_decoder.onnx \
  --cold-root-public <32-byte-hex> \
  --cold-root-signature <64-byte-hex>
```

The script prints the proposed hash/spec and writes a signed proposal only. The operator must listen first and attest that the current voice is the Paul Bettany clone before applying the proposal. Voice synthesis code, weights, and hyperparameters are not changed by this process.
